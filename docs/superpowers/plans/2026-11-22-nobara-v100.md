# Nobara port and Claude V100 launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Claude Endpoint Mapper to Nobara (Python) and add a separate "Claude V100" Claude Desktop launcher.

**Architecture:** `claude-v100` runs the stock `/usr/bin/claude-desktop` with `--profile=v100 --3p`. A stdlib-only Python engine writes the 3p gateway config, the RPM's `allowNonAnthropicModels` opt-in, and Claude Code settings; a Tk GUI and argparse CLI sit on top. No asar patching (the RPM ships the switch).

**Tech Stack:** Python 3 stdlib (`unittest`, `tkinter`, `urllib`, `argparse`), bash.

**Spec:** `docs/superpowers/specs/2026-11-22-nobara-v100-design.md`

## Global Constraints

- No sudo; never write under `/usr`; never modify `app.asar`. Stock Claude Desktop and its RPM stay untouched.
- Python 3 stdlib only. No `pwsh`. Windows files (`*.ps1`, `*.psm1`) are not modified.
- Never print or log API keys. Files holding a key are mode `0600`.
- V100 profile name is `v100`: userData `~/.config/Claude-v100`, 3p dir `~/.config/Claude-v100-3p` (config library `configLibrary/`, extra pref `claude-desktop-extra.json`), Claude Code dir `~/.claude-v100`.
- Tiers: `sonnet opus haiku fable mythos`; model dicts are `{"name": str, "tier": str, "label": str}`.
- No commits unless the user asks.

## Review Focus

- Re-running `apply` is idempotent (no duplicated models, servers or keys).
- Stopping V100 must never kill stock Claude (match only `--user-data-dir=<...>/Claude-v100` in cmdline).
- Existing `settings.json` / config / extra json with invalid JSON must not be silently overwritten; unrelated keys and other `managedMcpServers` entries survive.
- Blank API key keeps the existing key (including `__sealed__:v1:...`); keys never appear in CLI output.
- Installed asar without the `__CDB_ALLOW_NONANTHROPIC__` switch (other package or future RPM): `status`/`apply` say so plainly instead of claiming success.
